## Open Minor

1. **Stale privacy row in the report.** `task-20a-report.md:59` still says the code never calls `UnitName("player")` and that the player unit is asked only for its position. The review asked for this line to be updated. The code and README are correct, so this is a documentation slip only.
2. **A secret spell ID tags corpse loot as `unknown`.** `Core.lua:363` sets `lastCast` to `unknown` on every secret player cast. Any boss corpse looted within 3 s of such a cast is then `unknown` instead of `corpse`. If Forever hides the player's own spell IDs inside instances, the acceptance row would arrive flagged rather than clean. It is still imported under the README rule, so nothing is lost. Consider recording `unknown` only when the cast could plausibly be a pickpocket or gather, or treating `unknown` from a cast with no matching loot kind as `corpse` plus a flag.
3. **A numeric filter read is reported as `nil`.** `Core.lua:680-685` accepts booleans only. A client that returned `1` or `0` would be logged as "nil … left as it was", which is misleading, and the collapsed-section step would be skipped. Forever returns booleans, so the run is unaffected. Logging the type in `detail` would make the failure readable.
4. **The scrub behaviour is tested only outside the repo.** `CollectorSampleTest` reads a hand-written fixture. The `Mockplayername` assertion cannot fail against it, and the real check is in the scratchpad harness. This is acceptable for a one-run tool. Copying the harness into `tools/collector` would keep the I1 guarantee testable later. Also note that header-name matching on the collapse restore (`:705`, `:727`) would re-collapse two same-named headers, which the trainer list does not normally have.
