# Java library preparation session

`LibraryPreparationWorkflow` connects the normal Java acquisition/build/export path without UI dependencies or application activation. Its immutable source plan and protected acquisition job belong to a `Session`. `prepare(session, cancel, progress)` rechecks selected pins and session metadata, obtains the production native preset and selected community files, acquires explicitly selected optional hotfix/schema inputs, prepares a fresh staged catalogue, and exports/verifies the compact runtime library.

Current preflight accepts only Forever beta `1.60.1.70450/enUS` with explicitly selected Wago export permission. Additional explicit local-installation and Blizzard CDN permissions are preserved; the review explains that this build acquires catalogue tables from Wago and does not extract catalogue tables from those other permitted sources. Selected WoW folders remain protected. Without Wago permission, local-only/CDN-only plans fail before any network or staging. Other games/builds, changed pins and unsupported community archive/baseline manifests also fail early. No unselected provider is authorized or substituted. Optional AtlasLoot and AllTheThings remain controlled by source selections and their existing reviewed acquisition manifests.

Raidbots raw snapshot, disclosed GitHub/WoWDBDefs schema dependency and conservative same-build overlay stages execute only when the new explicit hotfix source is selected. They never inherit permission from Wago or CDN. A native-table-only review explains the measured 73% versus unchanged 85% coverage gate and never selects another provider automatically. Actual projection/validation remains authoritative.

Retries reuse the same in-memory session's checked acquisition cache. Every catalogue attempt has a new protected job directory, source archive, candidate and runtime path, even after a previous projection/export failure. No partial database is reused and no projection resume or restart recovery is claimed. The session exposes its last catalogue job for failure diagnosis; this is not a persistent recovery cursor. Failed attempts, complete source caches and previous candidate files remain available. A concurrent attempt on the same session is refused.

Progress reports real backend phase/file/count/byte observations. Runtime compaction and existing capture/projection stages remain indeterminate internally; cancellation is honored at their existing safe boundaries. Download/copy/hash stages poll more frequently. UI code can map these phases into its own visual groups without inventing a global percentage or claiming immediate SQL/projection cancellation.

Before catalogue capture, `acquisition-report.properties` records actual completed response-body download bytes, community bundle cache reuse, Wago table download/reuse counts, selected pins and optional raw/schema cache proofs. After a verified runtime export, `preparation-receipt.properties` records full candidate/archive/runtime paths and hashes, runtime export retained-table digests, omitted raw counts and actual validation/coverage warnings. The returned `Prepared` includes the plan, both protected job contexts, full candidate, verified compact export and acquisition report. No full staging files are removed before separate app-controlled activation.

This importer slice does not register a library, switch an open session or activate anything. The application adapter must independently enforce the selected source review and use its activation workflow after actual candidate acceptance. Authored orchestration fixtures test sequencing, consent, retries, cancellation and isolation; they are not real-data pipeline acceptance evidence.
