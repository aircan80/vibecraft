# Geographic sibling navigation (Refs #3)

The geographic breadcrumb keeps parent names and sibling arrows separate. Parent links preserve their existing navigation targets. Each arrow opens a native keyboard-accessible menu of recorded siblings; the selected location is marked, unavailable map records remain visible but disabled, and Escape closes the menu and returns focus to the arrow. No arrow is shown for an empty or singleton collection.

World-map choices come exclusively from the immutable `WorldMapCatalog` already loaded by the controller's worker. Unplaced recorded peers, including Zephras Isle where present in that catalogue, are included without assigning a map position. World-map artwork, marker geometry, map legend, and single outer scroll are unchanged.

Zone and district choices are attached to the existing `GeographyStep` objects during `ZoneRepository.breadcrumbs`' worker-side database read. District lists use the recorded `zone.parent_id` and existing `idx_zone_parent`; root zone lists require recorded UiMap parent relationships and select only root zone candidates. Map ancestors use recorded UiMap parents and only enable destinations with an installed zone or recorded descendants. Missing and cyclic parents do not create a hierarchy. Each query has a 1,001-row sentinel; a parent group exceeding 1,000 suppresses its menu instead of presenting a partial list as complete. No SQL is executed by a breadcrumb action or by popup construction.

Coverage: world-map pages, Journal zone/city map pages, zone records, and instance geographic trails reuse `BreadcrumbTrail` and gain the supplied sibling choices. The instance name itself has no supplied instance-sibling list. Generic NPC/item/quest detail pages that do not currently carry a geographic breadcrumb are unchanged. The global Journal section breadcrumb remains a section hierarchy and does not acquire geographic guesses.

Focused verification covers independent parent/sibling navigation, selected and disabled entries, keyboard action bindings, compact wrapping at 200/420 pixels, a real-catalog unplaced peer, immutable database-loaded choices, recorded district separation, and `EXPLAIN QUERY PLAN` use of `idx_zone_parent`. Native popup focus/keyboard and final artifact screenshots remain a separate acceptance step.

Validation completed for this change: the focused Maven run passed all 44 tests across `BreadcrumbTrailTest`, `WorldMapPageTest`, `GeographyBreadcrumbsTest`, `JournalWorldMapPageTest`, `JournalMapInspectorTest`, and `DetailPanelsTest`, with no failures, errors, or skips. An independent native component harness on isolated X11 display `:95` passed 24 keyboard assertions and captured four popup screenshots (dark/light, 420/1280 widths). It verified Down opens the menu, the current item is selected, Escape closes it and restores arrow focus, and keyboard selection opens the real target and closes the menu. Those screenshots use labelled geographic fixtures; they are component acceptance, not proof of a frozen release artifact.

Read-only warm query measurements against the installed development database (20 iterations each): district sibling lookup returned one row in 0.011 ms median; root-zone siblings returned 26 rows in 0.093 ms; map peers returned three rows in 0.132 ms. `EXPLAIN QUERY PLAN` used `idx_zone_parent` for district/root-zone candidates and primary-key map resolution; the small UiMap peer/child relation is scanned. These are local query measurements, not end-to-end page-load timings.
